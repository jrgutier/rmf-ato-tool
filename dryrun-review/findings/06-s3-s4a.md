### F-06-1: Passing MLEV-001 required re-recording three providers' arrangement, which also pulled in RECIP-001 obligations (evidence for F-05-1)
- Where: S-3 (orchestrator ruling); C-1's `artifacts/data/leveraged-authorizations.yaml` LA-02, LA-03, LA-04; MLEV-001 (`monitor.py` 252-279); RECIP-001 (`receiving.py` 76-115); `playbooks/C/C-1.md` step 7
- Kind: defect
- Severity: major
- What happened: As the orchestrator ruled, I re-recorded the access point (LA-02) and the software factory (LA-03) as `organizational-system`, and the CSSP (LA-04) as `external-service`. MLEV-001 then passed. The change was defensible, since each is a separately authorized DoD system or a service under agreement (INT-084.A1). But it came from the rule, not from the facts: P-5 still lists all three as approved common control providers, and ART-SD still says "each an approved common control provider of P-5". Changing the arrangement brought in obligations the old value did not have:
  - `organizational-system` needs `authorization_termination_date` and `ao_aware` (MLEV-001). The product gives no ATO end dates, so I added ASM-017 (three-year ATOs, fictional).
  - Every arrangement other than `common-control-provider` needs a `package_review` (RECIP-001), with factors, the integrating component of each boundary record, and both privacy overlays.

  So the value of `arrangement` decides whether the customer must review the provider's package at all. Today the rule makes that choice on the basis of whether some allocation is `common`.
- Workaround used: INT-084 (ISSM: arrangement, package reviews, end dates), INT-085 (AODR: the AO made aware), ASM-017, and package reviews for LA-02 to LA-04. Allocations stay hybrid. ART-SD was not rewritten, because S-3 does not touch it and its sentence stays true of P-5's list. Check: MLEV-001, RECIP-001, OCTX-004/005, C-1, S-3, P-2 and P-5 were all at 0 errors on the first cycle.
- Recommendation: As in F-05-1, count `hybrid` allocations in MLEV-001. Also say in the C-1 playbook and the schema which arrangement a provider of partial (hybrid) controls takes, and whether RECIP-001's package review applies to an internal DoD common control provider, rather than letting a provider's controls being only partial decide it.

### F-06-5: PVAL-001 compares only the first amount in a parameter that holds one value per authenticator type
